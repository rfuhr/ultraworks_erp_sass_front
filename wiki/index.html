Guia rápido

Como subir o frontend

Este é o guia operacional do template Angular. Ele cobre o ambiente local, as credenciais de demonstração, os comandos de qualidade e a publicação do build de produção.

Começar agora Ver todos os comandos
01

Pré-requisitos

Ferramentas

  • Node.js 22+ (recomendado LTS)
  • pnpm 11+ (corepack enable resolve)
  • Git para versionamento

Verificação rápida

node --version
pnpm --version

Se pnpm não existir, rode corepack enable.

02

Rodando localmente

Na raiz do repositório, instale as dependências uma única vez e suba o servidor de desenvolvimento: 

# instala as dependências
pnpm install

# sobe o app Angular em modo desenvolvimento
pnpm start
i
URL de acesso Abra http://localhost:4200. A rota inicial redireciona para /login.

pnpm start executa ng serve frontend. Se a porta 4200 estiver ocupada, use pnpm start -- --port 4300.

03

Acesso de demonstração

A autenticação é mockada e não chama backend. Use as credenciais abaixo:

E-mail demo@frontend.dev
Senha demo1234
!
A sessão fica apenas em memória Ao recarregar a página, você volta para o login. Esse comportamento é intencional nesta demonstração.

Fluxo esperado

  1. Abrir o app Acesse http://localhost:4200; você será levado ao login.
  2. Entrar Informe as credenciais de demonstração e clique em Entrar.
  3. Explorar o shell Navegue pela home, abra o sino de notificações para ler os avisos e clique no nome do usuário para abrir o menu de perfil.
  4. Sair Use a ação Sair no rodapé da sidebar para encerrar a sessão.
04

Comandos úteis

Comando O que faz
pnpm start Sobe o app em desenvolvimento em localhost:4200.
pnpm build Gera o build de produção em dist/frontend.
pnpm test Executa os testes unitários com Jest.
pnpm test:coverage Roda os testes com relatório de cobertura.
pnpm e2e Executa os testes E2E com Playwright (sobe o dev server).
pnpm lint Analisa o código com ESLint.
pnpm typecheck Valida os tipos com TypeScript.
pnpm storybook Abre o Storybook da biblioteca uw-ui.
✓
Antes de abrir um PR Rode pnpm lint, pnpm typecheck, pnpm test e pnpm build.
05

Build e produção

Gere o build otimizado e sirva os arquivos estáticos:

pnpm build
npx http-server dist/frontend/browser -p 8080

Acesse http://localhost:8080. Em produção real, use nginx ou outro servidor estático com fallback para index.html.

Configuração por ambiente

As URLs de API ficam em apps/frontend/src/environments/. Revise environment.production.ts antes de publicar.

06

Docker

O repositório já inclui Dockerfile multi-stage (Node + nginx) e nginx.conf com fallback de SPA. 

# constrói a imagem
docker build -t frontend-template .

# executa em http://localhost:8080
docker run --rm -p 8080:80 frontend-template

08

Problemas comuns

pnpm não é reconhecido
Rode corepack enable e tente novamente. Se necessário, instale com npm install -g pnpm.
A porta 4200 já está em uso
Suba em outra porta com pnpm start -- --port 4300 ou encerre o processo que está usando a 4200.
O login não autentica
Confirme o e-mail demo@frontend.dev e a senha demo1234. A validação é local; não há backend.
Recarreguei a página e voltei ao login
É o comportamento esperado: a sessão de demonstração existe apenas em memória e não é persistida.
Os testes E2E não iniciam
O Playwright sobe o dev server automaticamente. Verifique se a porta 4200 está livre e se os navegadores estão instalados com npx playwright install.
A rota interna retorna 404 ao servir o build
O servidor precisa de fallback para index.html. O nginx.conf do projeto já faz isso; em outros servidores, configure o fallback de SPA.
09

Observações da demonstração

O que é mockado

  • Login e sessão (em memória)
  • Usuário, menu e notificações do shell
  • Indicadores, atividades e progresso da home

O que é real

  • Design system e componentes uw-ui
  • Rotas lazy, guard e i18n
  • Testes unitários, E2E e Storybook
i
Próximo passo Para trocar o mock por uma API real, substitua o provider de LOGIN_REPOSITORY na rota de login por um repositório HTTP, conforme o ADR-0016.
